# v0.3.0 implementation milestones

All features in this plan are implementable with the current Electron + JupyterLab architecture. The implementation deliberately keeps persistent user data outside replaceable application files.

## M0 — Persistence and migration

- Minimal new `solution.ipynb`: one empty Python code cell; Workbench identity lives in notebook metadata.
- Existing `solution.ipynb` files are never rewritten by workspace migration.
- `problem.json` schema tracks status, saved-solution count, Run All count and last duration.
- Installed builds keep notebooks under `Documents/Project Euler Workspace` and Workbench settings/user packages under Electron `userData`.
- Portable builds keep all persistent state under neighboring `data/`.

Tests: workspace preservation, storage-mode path isolation, stable installed-mode marker.

## M1 — Daily problem workflow

- Top problem status (`Not Started`, `In Progress`, `Solved`).
- Local dashboard.
- `Run All + Save` through JupyterLab's command interface, with elapsed time recorded after completion.
- Global IPython `submit(value)` injected by Workbench; it talks only to a tokenized `127.0.0.1` bridge. Electron fills the Project Euler answer input but never clicks the site's submit control.

Tests: metadata/run timing, generated submit startup, Jupyter smoke test for the localhost submit bridge.

## M2 — Multiple solutions and personal knowledge

- `solution.ipynb` remains the editable working/draft notebook.
- Explicit `Save as Solution` creates stable `solutions/s001.ipynb`, `s002`, etc.; no automatic solution version spam.
- User-only snippet library. Workbench ships no algorithm snippets; a snippet can only be created from the active user-written Jupyter cell.
- Full-text search across working notebooks, saved solutions, user snippets and generated Markdown articles.
- Statistics derived from local metadata.

Tests: immutable snapshots, stable IDs, snippet provenance, cross-artifact search, statistics aggregation.

## M3 — Managed Python packages

- GUI package management executes the bundled interpreter's `python -m pip`.
- Installs/upgrades use `pip install --target <persistent python-packages>`.
- Package listing uses `pip list --path <persistent python-packages>`.
- Jupyter Server itself never imports from that directory; only the Euler Python kernel receives it as `PYTHONPATH`.
- Uninstall reads only a matching distribution's `.dist-info/RECORD` inside the managed layer and refuses to delete any path outside that layer. It never invokes a general `pip uninstall` against the bundled environment.

Tests: input validation, managed distribution deletion, path-escape protection, kernel/server import-path separation.

## M4 — AI articles

- User supplies a full OpenAI-compatible completion endpoint URL and custom model.
- User explicitly chooses the current working notebook and/or saved solutions to send.
- Code and Markdown cell source are sent; Project Euler pages are not scraped for AI.
- Generated output is stored as independent editable Markdown under `articles/aNNN/`.
- Multiple selected sources produce a comparison-analysis request.
- API keys are session-only by default. Optional remembered keys use Electron OS secure storage; plaintext keys are never written to settings JSON.

Tests: local mock completion endpoint, prompt/source boundaries, compatible response parsing, encrypted-at-rest configuration, article persistence/editing.

## M5 — Release and upgrade validation

Windows release remains:

- NSIS installer
- portable ZIP

Linux remains portable `tar.gz`; macOS is not built.

Installed upgrades use the same stable Electron Builder `appId`; program files/runtime are replaceable while notebooks, Electron data, AI settings and managed Python packages live outside the installation directory. `deleteAppDataOnUninstall` remains disabled.

Portable upgrades must preserve the existing `data/` directory. Release archives intentionally contain no `data/`, so extracting a new archive over the program files does not supply or replace user data. Users should close the application before either upgrade path.
